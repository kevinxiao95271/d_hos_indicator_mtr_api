# B15字段日期比较修复报告

## 问题描述

d_mr表中的B15字段（出院日期）数据类型为 **varchar(40)**，而不是DATETIME或TIMESTAMP类型。

在所有指标项SQL中使用 `B15 BETWEEN #{startDate} AND #{endDate}` 进行日期范围查询时，由于字段类型不匹配，可能导致查询结果不准确。

## 问题分析

### 字段信息
- **表名**: d_mr
- **字段名**: B15
- **数据类型**: varchar(40)
- **用途**: 出院日期

### 影响范围
- 所有48个指标项的query_sql字段
- 所有使用B15进行日期范围过滤的查询

### 问题示例
```sql
-- 原SQL（不推荐）
WHERE B15 BETWEEN '2023-01-01' AND '2023-12-31'

-- 问题：varchar类型的字符串比较，而非日期比较
-- 如果B15格式不规范（如 '2023-1-1' vs '2023-01-01'），可能导致错误结果
```

## 修复方案

### 采用的方案
使用 `DATE()` 函数将varchar类型的B15字段转换为DATE类型后再进行比较：

```sql
-- 修复后的SQL（推荐）
WHERE DATE(B15) BETWEEN '2023-01-01' AND '2023-12-31'
```

### 修复规则
1. `WHERE B15 BETWEEN` → `WHERE DATE(B15) BETWEEN`
2. `WHERE d_mr.B15 BETWEEN` → `WHERE DATE(d_mr.B15) BETWEEN`
3. `AND B15 BETWEEN` → `AND DATE(B15) BETWEEN`
4. `AND d_mr.B15 BETWEEN` → `AND DATE(d_mr.B15) BETWEEN`

## 影响评估

### 修复前的潜在问题
1. 如果B15字段值格式不统一（如 '2023-1-1' vs '2023-01-01'），字符串比较可能遗漏数据
2. 字符串比较性能低于日期比较
3. 可能导致指标计算结果不准确

### 修复后的改进
1. ✅ 使用DATE()函数确保日期比较的准确性
2. ✅ 自动处理不同的日期格式
3. ✅ 查询结果更可靠
4. ✅ 符合SQL最佳实践

### 性能影响
- 轻微影响：DATE()函数需要在每行上执行转换
- 建议：如果性能成为问题，可考虑：
  - 为B15字段添加函数索引: `ALTER TABLE d_mr ADD INDEX idx_b15_date ((DATE(B15)))`
  - 或修改表结构，将B15改为DATE/DATETIME类型
